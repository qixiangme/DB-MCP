# 첨부 Claude Code 가이드에서 가져온 검증 방법

## 사용 범위

사용자가 제공한 1,211줄짜리 가이드는 Claude Code의 설치, 세션, effort, 권한, 컨텍스트,
TDD, 훅, Git, CI, worktree, MCP, 서브에이전트 등을 설명하고, 별첨에서는 도구 실행 전
입력 검증과 권한 확인, 실행 후 결과 반환의 반복 루프를 강조합니다.

이 문서는 그 자료에 포함된 비공개 구현 주장이나 유출 소스 분석을 사실 근거로 재배포하지
않습니다. 공개적으로 검증 가능한 일반 작업 방식만 이 저장소의 평가 절차로 변환합니다.

## DB-MCP용 evaluator-optimizer 루프

1. **격리**: 후보마다 로컬 브랜치를 만들고 기준 커밋과 설정을 기록합니다.
2. **명세**: 목표 지표, 회귀 한도, 실패 시 안전한 기본 경로를 먼저 적습니다.
3. **실행**: 같은 모델, temperature, 데이터 분할, 반복 수로 기준선과 후보를 실행합니다.
4. **관찰**: 문항별 실제 라우트, 파싱 실패, 지연을 원시 JSON으로 저장합니다.
5. **평가**: 공개 개발셋의 혼동 행렬을 보고 한 번에 한 원인만 수정합니다.
6. **검증**: 단위 테스트와 기존 공식셋을 통과한 뒤 보류셋을 평가합니다.
7. **중단**: 90% 미달, 회귀, 오류 증가 시 후보를 채택하지 않고 실패 원인을 남깁니다.

## 안전 체크

- 모델 출력은 신뢰하지 않고 `SQL|VECTOR|GRAPH` 정확 라벨만 허용합니다.
- 시간 초과, 연결 실패, 파싱 실패는 문서 검색(VECTOR)으로 복구하고 오류를 기록합니다.
- 평가 데이터는 프롬프트나 규칙 생성 입력으로 사용하지 않습니다.
- 벤치마크를 통과시키기 위한 정답 하드코딩을 검사합니다.
- 결과 파일에는 브랜치, 커밋, 모델, 설정, 실행 시각을 남깁니다.

## 후보별 로컬 브랜치

| 브랜치 | 독립 변수 |
|---|---|
| `chore/contribution-governance` | 이슈·PR·리뷰 안전 체계 |
| `docs/semantic-routing-research` | 연구 근거와 검증 계획 |
| `benchmark/router-eval-harness` | 누수 방지 라우팅 평가기 |
| `feature/semantic-ai-router` | 의미 설명·균형 예시 AI 분류 |
| `integration/keywordless-routing` | 검증된 변경만 모은 통합본 |

브랜치가 존재한다는 사실은 성공을 뜻하지 않습니다. 각 브랜치의 커밋과 결과 보고서를 함께
확인해야 하며, 원격 push와 PR 생성은 별도 승인 범위입니다.
